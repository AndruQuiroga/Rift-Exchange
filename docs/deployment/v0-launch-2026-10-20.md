invite-only. Git manifests and private SSH are the deployment path for this new
stack; existing Portainer-managed applications were not redeployed or adopted.

## Backup verification

The database and daily backup service use separate configured nodes and dedicated
node-local volumes. A scheduled custom-format dump of 99,559 bytes was exported
to ignored local storage and restored into isolated PostgreSQL 16. The restored
revision, season, 46 fixtures and 73 markets matched; ledger reconciliation found
no mismatches. Backup container health passed.

Daily backups retain about fourteen days. They remain in the same rack, so this
does not establish protection against rack-wide loss or database failover. Future
updates take a pre-migration dump and force an immediate post-migration scheduled
backup. Review accumulation of pre-release snapshots separately.

## Limits and next changes

- First real signed-in production use remains for the owner to verify with their
  private invite. Authenticated production ticket writes and SSE reconnect were
  not exercised during deployment; the isolated full-flow test passed.
- V0 has no returning-account login/recovery flow. Sessions last 60 days; preserve
  cookies and avoid signing out until that feature is added. A used invite cannot
  sign an existing user back in.
- Leaguepedia stays in mock/unavailable mode pending bot credentials; do not infer
  coverage for dependent market families from the core worker health result.
- No load, node failover, rack outage or external backup-destination test was run.
- Private management inventory and invite values are excluded from the repository.

For subsequent releases, follow [the SSH deployment guide](../../infra/stache/README.md).
Use validated image digests and a new release ID; never bypass the migration gate
or restore/downgrade the database automatically during an image rollback.
